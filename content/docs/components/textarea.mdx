## When to use

Use a textarea when people need to explain something in their own words, usually in more than one sentence.

Use something else when:

- **The answer is short.** Use a [Text input](/docs/components/text-input).
- **People are choosing from a list.** Use a [Radio group](/docs/components/radio-group) or [Select](/docs/components/select).

## Usage

Put the textarea in a [Field](/docs/components/field), so its label, hint, errors and count are linked to it.

```tsx
import {
  Field,
  FieldDescription,
  FieldError,
  FieldLabel,
} from "@/components/ui/field";
import { Textarea } from "@/components/ui/textarea";

<Field>
  <FieldLabel required>Why do you need a new copy?</FieldLabel>
  <Textarea required />
  <FieldDescription>
    A few sentences is enough. Don't include ID numbers.
  </FieldDescription>
  <FieldError match="valueMissing">Tell us why you need a new copy.</FieldError>
</Field>;
```

The textarea starts 4 lines tall and grows as people type. In browsers that can't grow it yet, like Firefox, it scrolls instead and people can drag it taller.

### Character count

Add a count when the service has a real limit, like a database column. Set `characterLimit` on the textarea, and put `TextareaCharacterCount` last in the field. The count needs the current value, so control it with `value` and `onValueChange`.

```tsx
"use client";

import { useState } from "react";
import {
  Field,
  FieldDescription,
  FieldLabel,
} from "@/components/ui/field";
import {
  Textarea,
  TextareaCharacterCount,
} from "@/components/ui/textarea";

const characterLimit = 500;

function ReasonField() {
  const [reason, setReason] = useState("");

  return (
    <Field>
      <FieldLabel>Why do you need a new copy?</FieldLabel>
      <Textarea
        value={reason}
        onValueChange={setReason}
        characterLimit={characterLimit}
      />
      <FieldDescription>
        A few sentences is enough. Don't include ID numbers.
      </FieldDescription>
      <TextareaCharacterCount
        value={reason}
        limit={characterLimit}
        overLimitMessage="Your reason is too long"
      />
    </Field>
  );
}
```

The limit doesn't stop people typing. Over the limit, the count goes negative and turns red, so people can see how much to remove.

## Content guidelines

- **Labels say what to explain:** "Why do you need a new copy?", not "Details".
- **Hints say what makes a useful answer:** give a length or content suggestion, and mention information people should leave out.
- **Don't put instructions in the placeholder.** They disappear when people start typing.
- **Set a useful limit.** Don't make people write more than the service needs.
- **Over-limit messages name the field:** "Your reason is too long", not "Too many characters".

## Accessibility

### What Habi handles

- **Labels, hints and errors** are linked to the textarea, so screen readers read them when it gets focus.
- **The limit is read with the label:** the count adds a hidden "You can enter up to 500 characters." to the textarea's description.
- **The count is read when people pause typing,** not on every key press, as "You have 12 characters remaining" or "You have 3 characters too many".
- **Over the limit isn't just red:** the count gets an error icon and a negative number.
- **Text size:** the textarea uses 16px text, so phones don't zoom in when people tap it.
- **Focus:** a 2px blue outline shows which field is active, even on a field with an error.

### What you need to do

- **Give every textarea a visible `FieldLabel`.** A placeholder isn't a label.
- **Check the limit when people submit,** and on your server. The tooltip only shows on hover, so it's extra help, not the error message.
- **Use Base UI's `Form`**, or your own submit handling, to move focus to the first field with an error after people submit.
