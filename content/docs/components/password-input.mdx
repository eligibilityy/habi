## When to use

Use a password input when people sign in, or create a password for an account.

Use something else when:

- **You send people a one-time code.** Use an [OTP input](/docs/components/otp-input).
- **The answer isn't secret.** Use a [Text input](/docs/components/text-input). Hiding what people type makes mistakes harder to spot.

## Usage

Put the password input in a [Field](/docs/components/field), so its label, hint and errors are linked to it.

```tsx
import {
  Field,
  FieldDescription,
  FieldError,
  FieldLabel,
} from "@/components/ui/field";
import { PasswordInput } from "@/components/ui/password-input";

<Field>
  <FieldLabel required>Password</FieldLabel>
  <PasswordInput required />
  <FieldError match="valueMissing">Enter your password.</FieldError>
</Field>;
```

The password is hidden until people press **Show**. It stays showing until they press **Hide**, or the form is sent. Hiding it on submit lets browsers offer to save it, and means it isn't showing if people come back to the page.

## Examples

### Creating a password

Set `autoComplete="new-password"`, so password managers can suggest a strong one. Put the rules in the hint, so people know them before they type. Check them when people submit: return a message from the field's `validate` function, and show it with `<FieldError match="customError">`.

## Content guidelines

- **Labels say what to do:** "Password" to sign in, "Create a password" when making one.
- **Put the rules in the hint,** like "At least 8 characters, with a number." Don't keep them back until people get one wrong.
- **Don't ask people to type it twice.** They can press Show to check it instead.
- **Errors say what to fix:** "Your password must include a number.", not "Invalid password."
- **Translate the button with the page:** set `showLabel` and `hideLabel` (like "Ipakita" and "Itago"), and the screen reader text below.

## Props

The label, hint and errors are [Field](/docs/components/field#props) parts. See their props there.

`PasswordInput` accepts the props of Base UI's [Input](https://base-ui.com/react/components/input), like `value`, `defaultValue`, `onValueChange`, `required` and `autoComplete`, except `type`.

## Accessibility

### What Habi handles

- **Labels, hints and errors** are linked to the field, so screen readers read them when it gets focus.
- **The Show button** is named "Show password" or "Hide password", and screen readers hear "Your password is showing." or "Your password is hidden." when people press it.
- **Password managers and pasting** keep working. The field never blocks paste, and spelling checks and auto-capitals are off, so the password isn't changed or sent to a spell checker while it's showing.
- **One reveal button:** Edge's own reveal button is hidden, so there aren't two.
- **Disabled fields** disable the Show button too.
- **Focus:** a 2px blue outline shows which field is active, and the Show button has its own outline.

### What you need to do

- **Give every password input a visible `FieldLabel`.** A placeholder isn't a label.
- **Set `autoComplete`** to `current-password` to sign in or `new-password` to create one (WCAG 1.3.5).
- **Don't set a maximum length** short enough to cut off a password from a password manager.
- **Use Base UI's `Form`**, or your own submit handling, to move focus to the first field with an error after people submit.
