## When to use

Use a radio group when people choose exactly one option and should see every choice:

- **Comparing options**, like picking up a document or having it delivered.
- **Choosing how to pay**, when each option has its own fee or timing.

Use something else when:

- **There are many options**, or long ones that crowd a small screen. Use a [Select](/docs/components/select). About five options is usually the limit, but long labels or hints under each option can tip it sooner.
- **People can pick more than one.** Use a [Checkbox](/docs/components/checkbox) group.

## Usage

```tsx
import {
  ChoiceLabel,
  Field,
  FieldItem,
  Fieldset,
  FieldsetLegend,
} from "@/components/ui/field";
import { Radio, RadioGroup } from "@/components/ui/radio";

<Field name="collection">
  <Fieldset render={<RadioGroup />}>
    <FieldsetLegend>How do you want to get your clearance?</FieldsetLegend>
    <FieldItem>
      <ChoiceLabel>
        <Radio value="pickup" />
        Pick up in person
      </ChoiceLabel>
    </FieldItem>
  </Fieldset>
</Field>;
```

## Content guidelines

- **The legend asks the question:** "How do you want to get your clearance?"
- **Options answer it in a few words:** "Pick up in person", "Have it delivered".
- **Put the most common option first**, unless there's a natural order, like cheapest to most expensive.
- **Don't preselect an option** when the choice has a cost or consequence, so people make it on purpose.

## Accessibility

### What Habi handles

- **Whole row:** `ChoiceLabel` wraps the radio and its text, so the full 48px row can be pressed.
- **Group question:** the legend names the group, so screen readers read the question with the options.
- **Keyboard:** <kbd>Tab</kbd> moves into the group, landing on the selected option. The arrow keys move between options and select them. <kbd>Tab</kbd> again leaves the group.
- **State:** the selected option has a filled dot, not just a color change.
- **Errors** appear below the group, with an icon and text, not just a red border.

### What you need to do

- **Ask the question in a `FieldsetLegend`**, so screen reader users hear it with the options.
- **Stack options vertically**, so they're easy to scan and compare.
- **Use Base UI's `Form`**, or your own submit handling, to move focus to the group after a failed submit.
