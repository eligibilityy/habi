## Installation

[Set up Habi](/docs/installation) first, if you haven't already.

Install the packages this component uses:

```npm
npm install @base-ui/react class-variance-authority
```

Add the component:

<ComponentSource
  src="registry/habi/ui/button.tsx"
  title="components/ui/button.tsx"
/>

## Usage

```tsx
import { Button } from "@/components/ui/button";

<Button>Book an appointment</Button>;
```

## Examples

### Kinds

Use **one primary button** per screen, for the main action. Use secondary and tertiary for other actions, subtle for low-emphasis ones, and danger only for actions that delete something or can't be undone.

<ComponentPreview name="button-kinds" />

### With an icon

Put the icon **before** the label for actions, like Download or Add. Put it **after** the label for moving forward, like Continue.

<ComponentPreview name="button-with-icon" />

### Icon only

Use these only where the icon is widely understood, like search or delete. Every icon-only button needs an `aria-label` that says what it does.

<ComponentPreview name="button-icon-only" />

### Disabled

Avoid disabled buttons where you can. People can't tell why a button doesn't work. It's usually better to let them press it and explain what's missing.

<ComponentPreview name="button-disabled" />

### As a link

If the button takes people to another page, use a link that looks like a button. Pass `buttonVariants` to your link's `className`. This works with `next/link`, your router's link component, or a plain `<a>` for external sites.

<ComponentPreview name="button-link" />

## Accessibility

- **Keyboard:** <kbd>Tab</kbd> moves focus to the button, and <kbd>Enter</kbd> or <kbd>Space</kbd> presses it. A 2px focus ring shows which button has focus.
- **Size:** buttons are 48px tall, well above the 24 x 24px minimum target size in WCAG 2.2.
- **Labels:** start with a verb and say what will happen: "Pay ₱145.00" instead of "Submit".
- **Forms:** buttons default to `type="button"`, so set `type="submit"` on the button that sends a form.
- **Icons** are hidden from screen readers, because the label already says what the button does. Icon-only buttons need an `aria-label`.
- **Links:** if it goes to another page, use a link styled with `buttonVariants`, not a Button. Screen readers then announce it as a link.
