## When to use

Use a button when pressing it does something:

- **Submitting a form**, like "Continue" or "Pay ₱145.00".
- **Starting a task**, like "Book an appointment".
- **Changing something on the page**, like "Add another child".

Use something else when:

- **It goes to another page.** Use a [Link](/docs/components/link). If it has to look like a button, style the link with [`buttonVariants`](#as-a-link). Screen readers then announce it as a link, which tells people what will happen.

## Installation

[Set up Habi](/docs/installation) first, if you haven't already. Then add the component with the shadcn CLI, which also adds the Habi parts it uses:

```npm
npx shadcn@latest add https://habi.yiliya.studio/r/button.json
```

To add it by hand instead, install the packages this component uses:

```npm
npm install @base-ui/react class-variance-authority
```

Add the component:

  src="registry/habi/ui/button.tsx"

## Usage

```tsx
import { Button } from "@/components/ui/button";

<Button>Book an appointment</Button>;
```

## Examples

### Kinds

Use **one primary button** per screen, for the main action, so people can see what to do next. Use secondary and tertiary for other actions, subtle for low-emphasis ones, and danger only for actions that delete something or can't be undone.

<ComponentPreview name="button-kinds" />

### With an icon

Put the icon **before** the label for actions, like Download or Add. Put it **after** the label for moving forward, like Continue.

<ComponentPreview name="button-with-icon" />

### Icon only

Use these only where the icon is widely understood, like search or delete. Every icon-only button needs an `aria-label` that says what it does.

<ComponentPreview name="button-icon-only" />

### Disabled

Avoid disabled buttons where you can. People can't tell why a button doesn't work. It's usually better to let them press it and explain what's missing.

<ComponentPreview name="button-disabled" />

### As a link

If the button takes people to another page, use a link that looks like a button. Pass `buttonVariants` to your link's `className`. This works with `next/link`, your router's link component, or a plain `<a>` for external sites.

<ComponentPreview name="button-link" />

## Content guidelines

- **Start with a verb** and say what will happen: "Pay ₱145.00", not "Submit".
- **Keep it short:** one to three words is usually enough. The page around the button explains the rest.
- **Use the same words as the task.** If the page is about booking an appointment, the button says "Book appointment", not "Proceed".

## Accessibility

### What Habi handles

- **Keyboard:** <kbd>Tab</kbd> moves focus to the button, and <kbd>Enter</kbd> or <kbd>Space</kbd> presses it. A 2px focus ring shows which button has focus.
- **Size:** buttons are 48px tall, well above the 24 × 24px minimum target size in WCAG 2.2.
- **Icons** are hidden from screen readers, because the label already says what the button does.

### What you need to do

- **Set `type="submit"`** on the button that sends a form. Buttons default to `type="button"`, so they don't submit forms by accident.
- **Give icon-only buttons an `aria-label`**, like "Search", so screen readers can name them.
- **Use a link for navigation**, styled with `buttonVariants` if needed, not a Button.
- **Prevent double submissions.** On slow connections people often press again when nothing seems to happen. After the first press, set `disabled` with `focusableWhenDisabled`, so focus stays on the button, and change the label to say what's happening, like "Paying…".
