## When to use

Use a date input for dates people know or can copy from a document:

- **Dates of birth.**
- **Dates printed on an ID or certificate**, like an issue or expiry date.

Use something else when:

- **People are choosing a date**, like an appointment. Show the dates they can book instead, so they don't pick one that isn't available.
  Don't use a calendar picker for dates of birth. Scrolling back decades is slow, and typing the year is quicker.

## Usage

```tsx
import { DateInput } from "@/components/ui/date-input";

<DateInput
  label="Date of birth"
  description="For example, 15 March 1990"
  name="dob"
  autoComplete="bday"
/>;
```

The value is an object of strings, like `{ day: "15", month: "3", year: "1990" }`. Months are numbered 1 to 12. Strings keep exactly what people typed, so you can show it back to them alongside an error.

With `name="dob"`, the form submits `dob-day`, `dob-month` and `dob-year`.

## Examples

### Validation

Date input doesn't check the date itself, because one message has to cover all three boxes. Check the value when people submit and pass the message to `error`. By default, `error` marks all three boxes. Pass `invalid` to mark only the boxes that are wrong.

Clear the error in `onValueChange`. Base UI's `Form` won't submit while any box is marked invalid, so an error that stays after people fix the date blocks the next submit.

## Content guidelines

- **The label names the date:** "Date of birth", "Date of issue".
- **The hint shows an example** in the same order as the boxes: "For example, 15 March 1990".
- **Error messages** cover one problem at a time, the first one people need to fix:

| Problem                                  | Message                             | Mark                |
| ---------------------------------------- | ----------------------------------- | ------------------- |
| Nothing entered                          | Enter your date of birth.           | All three           |
| A part is missing                        | Date of birth must include a month. | The missing part(s) |
| The year isn't 4 digits                  | Year must include 4 numbers.        | Year                |
| The date doesn't exist, like 31 February | Date of birth must be a real date.  | Day                 |
| The date is in the future                | Date of birth must be in the past.  | All three           |

Replace "date of birth" with the field's own name, like "issue date".

## Accessibility

### What Habi handles

- **Group:** the boxes sit in a fieldset named by the label. The hint and any error are linked to it with `aria-describedby`, and each box has its own label: "Day", "Month" or "Year".
- **Number keypad:** Day and Year use `inputMode="numeric"`, so phones show the number keypad. They aren't `type="number"`, which adds spinner arrows and changes the value when people scroll.
- **Keyboard:** <kbd>Tab</kbd> moves from Day to Month to Year. The month list works like a [Select](/docs/components/select#accessibility): arrow keys move, typing a letter jumps to a month, and <kbd>Enter</kbd> chooses.
- **Month names:** months are listed by name, so nobody has to work out whether 03 is March. They're in English for now.
- **Errors aren't just red:** the message has an icon and text.
- **Small screens:** the three boxes take 336px, so they fit on one row on a 375px-wide phone.

### What you need to do

- **Check the date on submit** and pass the message to `error`, marking only the wrong boxes with `invalid`.
- **Move focus to the first invalid box** after a failed submit, as the validation example does.
- **Clear the error when people change the date**, so the next submit isn't blocked.
