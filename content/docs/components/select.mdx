## When to use

Use a select when people choose one option from a list that's too long to show all at once:

- **Places**, like a region or province.
- **Types of document**, like which valid ID someone will bring.

Use something else when:

- **People should compare the options**, or there are only a few. Use a [Radio group](/docs/components/radio-group), which shows every choice without opening anything. About five options is usually where a radio group starts to take too much space, but long labels or a small screen can tip it sooner.
- **The list is very long**, like every city and municipality. Use a search field, so people can type to filter instead of scrolling.
- **People can pick more than one.** Use a [Checkbox](/docs/components/checkbox) group.

## Usage

```tsx
import { Field } from "@/components/ui/field";
import {
  Select,
  SelectContent,
  SelectItem,
  SelectLabel,
  SelectTrigger,
  SelectValue,
} from "@/components/ui/select";

const regions = [
  { value: "ncr", label: "National Capital Region (NCR)" },
  { value: "r7", label: "Central Visayas (Region VII)" },
];

<Field>
  <SelectLabel>Region</SelectLabel>
  <Select items={regions}>
    <SelectTrigger>
      <SelectValue placeholder="Select a region" />
    </SelectTrigger>
    <SelectContent>
      {regions.map((region) => (
        <SelectItem key={region.value} value={region.value}>
          {region.label}
        </SelectItem>
      ))}
    </SelectContent>
  </Select>
</Field>;
```

Pass the same list to `items`, so the field shows the chosen label instead of its value.

## Content guidelines

- **The label names the answer:** "Region", not "Select your region".
- **The placeholder asks for a choice:** "Select a region".
- **Order options so they're easy to find:** alphabetically, or in an order people already know, like regions from north to south.
- **Keep option labels short and distinct**, so they don't get cut off and people can tell them apart.

## Accessibility

### What Habi handles

- **Keyboard:** <kbd>Enter</kbd>, <kbd>Space</kbd> or <kbd>↓</kbd> opens the list. Arrow keys move, typing a letter jumps to matching options, <kbd>Enter</kbd> chooses, and <kbd>Esc</kbd> closes it. Focus returns to the field.
- **Label:** `SelectLabel` names the field for screen readers. Clicking it moves focus to the field without opening the list.
- **Selected option:** shown with a check and a blue background, not just color.
- **Errors** appear below the field, with an icon and text, not just a red border.
- **Small screens:** the list never runs past the edge of the screen. It flips above the field and scrolls when space is short.
- **Motion:** the open and close fade is turned off for people who prefer reduced motion.

### What you need to do

- **Give every select a `SelectLabel`.** The placeholder disappears once people choose.
- **Pass `items`**, so the field and screen readers show the chosen label, not its value.
- **Use Base UI's `Form`**, or your own submit handling, to move focus to the field after a failed submit.
