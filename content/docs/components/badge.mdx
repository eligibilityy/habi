## When to use

Use a badge to show the status of something nearby:

- **A service's availability**, like "Open" or "Closing soon".
- **Something new**, like "New" next to an announcement.
- **An application's state**, like "Approved" or "Needs action".

Use something else when:

- **People can select it**, like a filter. Use a [Tag](/docs/components/tag).
- **People need to know what happened** after an action, or what to do next. Use a [Notification](/docs/components/notification), which has room for an explanation.

## Installation

[Set up Habi](/docs/installation) first, if you haven't already. Then add the component with the shadcn CLI, which also adds the Habi parts it uses:

```npm
npx shadcn@latest add https://habi.yiliya.studio/r/badge.json
```

To add it by hand instead, install the packages this component uses:

```npm
npm install class-variance-authority
```

Add the component:

  src="registry/habi/ui/badge.tsx"

## Usage

```tsx
import { Badge } from "@/components/ui/badge";

<Badge kind="success">Open</Badge>;
```

## Content guidelines

- **One or two words:** badges don't wrap, and short labels are quicker to scan.
- **Describe the state, not an action:** "Closed", not "Can't apply".
- **Use the same words for the same state** across the service, so people learn what each one means.

## Accessibility

### What Habi handles

- **Contrast:** every kind's text and background pass WCAG AA (5.3–6.8:1).
- **Not interactive:** badges can't be clicked or focused, so they don't add stops for keyboard users.
- **Icons** are hidden from screen readers, so the label is read once without a meaningless icon name.

### What you need to do

- **Let the words carry the meaning.** Color only reinforces it, so a badge still makes sense in grayscale or to people who can't tell colors apart (WCAG 1.4.1).
- **Add context for screen readers** with visually hidden text (`sr-only`) when the badge only makes sense next to something else, like "Status: Open".
