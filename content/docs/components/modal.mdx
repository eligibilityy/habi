## When to use

Use a modal for something people must deal with before they go on:

- **Confirming an action that's hard to undo:** "Cancel this appointment?"
- **A short task** that belongs to the current page, like changing a mobile number.

Use something else when:

- **The task is long**, like a whole application form. Give it its own page.
- **People need to read the page behind it** to answer. Put the question on the page.
- **It's only information.** Use a [Notification](/docs/components/notification).
- **People didn't ask for it,** like a newsletter sign-up. Don't interrupt them.

## Usage

```tsx
import { Button } from "@/components/ui/button";
import {
  Modal,
  ModalBody,
  ModalClose,
  ModalContent,
  ModalDescription,
  ModalFooter,
  ModalTitle,
  ModalTrigger,
} from "@/components/ui/modal";

<Modal>
  <ModalTrigger render={<Button kind="tertiary" />}>
    Cancel appointment
  </ModalTrigger>
  <ModalContent>
    <ModalTitle>Cancel this appointment?</ModalTitle>
    <ModalBody>
      <ModalDescription>
        Your appointment on 15 December 2026 will be released to other
        applicants.
      </ModalDescription>
    </ModalBody>
    <ModalFooter>
      <ModalClose render={<Button kind="secondary" />}>
        Keep appointment
      </ModalClose>
      <Button kind="danger" onClick={cancelAppointment}>
        Cancel appointment
      </Button>
    </ModalFooter>
  </ModalContent>
</Modal>;
```

From 640px wide, the modal is a 560px panel in the middle of the screen, with its buttons on the right. On phones it's a sheet along the bottom of the screen, with full-width buttons and the main action on top.

## Content guidelines

- **The title asks the question** or names the task: "Cancel this appointment?", "Change your mobile number".
- **The description says what will happen,** with the details people need to decide: dates, amounts, what they'll lose.
- **Each button says what it does:** "Keep appointment" and "Cancel appointment", not "OK" and "Cancel".
- **Use the Danger kind** for the main button when the action can't be undone.

### ModalTitle, ModalBody, ModalDescription and ModalFooter

Each takes `children`. `ModalTitle` is the modal's heading, `ModalBody` holds any content, `ModalDescription` is the text that explains the title, and `ModalFooter` holds the buttons.

## Accessibility

### What Habi handles

- **Focus moves into the modal** when it opens, stays inside while it's open, and goes back to the button that opened it when it closes.
- **The page behind can't be used** while the modal is open.
- **<kbd>Esc</kbd> and the close button close it.** The close button is named "Close" and is 32 × 32px.
- **Names:** screen readers read `ModalTitle` as the modal's name and `ModalDescription` as its description as soon as it opens.
- **Reduced motion:** the modal opens and closes without moving when people ask their device for less motion.

### What you need to do

- **Always add a `ModalTitle`.** It's how screen readers name the modal.
- **Put the safe choice first** in `ModalFooter`, like "Keep appointment". It comes first for screen readers and keyboard users, and phones show the main action on top.
- **Translate `closeLabel`** when the page isn't in English.
