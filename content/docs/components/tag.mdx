## When to use

Use tags to let people narrow down what they see:

- **Filtering a list of services**, like Passport, IDs or Taxes.
- **Filtering search results** by category or office.

Tags change what's shown on the page straight away, without a submit button.

Use something else when:

- **It's a status people can't change**, like "Open". Use a [Badge](/docs/components/badge).
- **It's a question in a form**, like which IDs someone has. Use a [Checkbox](/docs/components/checkbox) group, which is submitted with the rest of the form and can show errors.

## Usage

```tsx
import { Tag, TagGroup } from "@/components/ui/tag";

<TagGroup multiple aria-label="Filter services">
  <Tag value="passport">Passport</Tag>
  <Tag value="ids">IDs</Tag>
</TagGroup>;
```

## Content guidelines

- **One or two words** per tag, like "Passport" or "Health".
- **Name the category, not an action:** "Taxes", not "Show taxes".

## Accessibility

### What Habi handles

- **State:** each tag is a toggle button. Screen readers announce whether it's pressed, and a check shows the selected state without relying on color.
- **Keyboard:** <kbd>Tab</kbd> moves into the group, the arrow keys move between tags, and <kbd>Space</kbd> or <kbd>Enter</kbd> turns a tag on or off.
- **Size:** tags are 32px tall with 8px gaps, above the 24 × 24px minimum target size in WCAG 2.2.

### What you need to do

- **Name the group:** give `TagGroup` an `aria-label`, like "Filter services", so screen reader users know what the tags do.
- **Announce the result** of a change, like the number of services shown, with `aria-live`. The tags themselves don't say what changed on the page.
