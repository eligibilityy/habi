## When to use

Use Search to help people find a service or page on a site with many of them, like an agency's list of online services.

Use something else when:

- **People must pick one option from a known list**, like their region. Use a [Select](/docs/components/select).
- **People are entering their own answer** in a form, like their name or address. Use a [Text input](/docs/components/text-input).

## Usage

```tsx
import { MagnifyingGlassIcon } from "@heroicons/react/20/solid";

import {
  Search,
  SearchContent,
  SearchEmpty,
  SearchInput,
  SearchItem,
  SearchItemDescription,
  SearchItemText,
  SearchList,
} from "@/components/ui/search";

type Service = { id: string; title: string; description: string };

const services: Service[] = [
  {
    id: "nbi",
    title: "NBI clearance",
    description: "Apply for or renew your clearance",
  },
  // …
];

<Search items={services} itemToStringValue={(service) => service.title}>
  <SearchInput
    aria-label="Search for a service"
    placeholder="Search for a service"
  />
  <SearchContent>
    <SearchEmpty>No services match your search.</SearchEmpty>
    <SearchList>
      {(service: Service) => (
        <SearchItem key={service.id} value={service}>
          <MagnifyingGlassIcon />
          <SearchItemText>
            {service.title}
            <SearchItemDescription>{service.description}</SearchItemDescription>
          </SearchItemText>
        </SearchItem>
      )}
    </SearchList>
  </SearchContent>
</Search>;
```

The parts:

- **`Search`** holds the list of `items` and filters it as people type. When items are objects, `itemToStringValue` says which text to match and to put in the field.
- **`SearchInput`** is the field, with the search icon and a clear button that appears once people type.
- **`SearchContent`** is the menu of suggestions below the field. `SearchList` renders one `SearchItem` per matching item.
- **`SearchItemText`** holds an item's title and an optional `SearchItemDescription`. Put an icon before it.
- **`SearchEmpty`** shows when nothing matches.

## Examples

### Search form

Put Search in a `<form role="search">` with a Search button, so people can see every result, not just the suggestions. Choosing a suggestion should take people straight to that service: handle it with the item's `onClick`, which also runs when people press <kbd>Enter</kbd> on a suggestion. Pressing <kbd>Enter</kbd> anywhere else submits the form.

<ComponentPreview name="search-form" />

### Keyboard shortcut

Add `shortcut` to `SearchInput` to let people jump to the search with <kbd>⌘</kbd> <kbd>K</kbd> on a Mac or iPhone, or <kbd>Ctrl</kbd> <kbd>K</kbd> elsewhere. The field shows the shortcut on devices with a mouse or trackpad, and hides it once people type. Try it in the first example on this page.

Use it for one search per page, usually the site search in the header. If another script on the page already handles the shortcut and marks the key press as handled, Search leaves it alone.

## Content guidelines

- **The placeholder says what people can find:** "Search for a service", not just "Search".
- **Suggestion titles use the service's everyday name:** "NBI clearance", not "Application for NBI Clearance Certificate".
- **Descriptions say what people can do there,** in a few words: "Apply for or renew your clearance".
- **The empty message says what to do next:** "No matching services. Press Search to see all results."

## Accessibility

### What Habi handles

- **Roles:** the field is a combobox that controls a list of suggestions, so screen readers say that suggestions are available and announce the one that's highlighted.
- **Keyboard:** <kbd>↓</kbd> and <kbd>↑</kbd> move through the suggestions while focus stays in the field. <kbd>Enter</kbd> chooses the highlighted suggestion. <kbd>Esc</kbd> closes the menu, and pressing it again clears the field.
- **No matches:** the `SearchEmpty` message is announced when it appears.
- **Clear button:** it's named "Clear search" and appears once people type. Pressing it clears the field and keeps focus there. It's skipped by <kbd>Tab</kbd>, because keyboard users can press <kbd>Esc</kbd> instead.
- **Shortcut:** with `shortcut`, the field has `aria-keyshortcuts`, so screen readers can announce the shortcut. The visible hint is hidden from them, to avoid saying it twice.
- **Phones:** the field uses `type="search"`, so phones show a Search key on the keyboard.

### What you need to do

- **Name the field** with `aria-label`, or a `FieldLabel` if the label is shown. A placeholder isn't a name.
- **Use `<form role="search">`** around the site search, so screen reader users can jump to it as a landmark.
- **Give people a way to see every result,** with a Search button, not only the suggestions.
- **Use `shortcut` once per page,** so the shortcut always goes to the same place.
- **Translate `clearLabel`** when the page isn't in English.
