## When to use

Use cards when people need to compare several things and pick one:

- **Services**, like "Renew your passport" or "Get an NBI clearance".
- **Offices or places**, like the nearest DFA consular office.
- **News and updates**, like a change to requirements.

Use something else when:

- **There's only one thing to show.** Put it on the page as headings and text. A single card adds a box without helping people compare.
- **People need to read a lot.** Cards hold a summary. Link to a full page for the details.

## Installation

[Set up Habi](/docs/installation) first, if you haven't already. Then add the component with the shadcn CLI, which also adds the Habi parts it uses:

```npm
npx shadcn@latest add https://habi.yiliya.studio/r/card.json
```

To add it by hand instead, install the packages this component uses:

```npm
npm install class-variance-authority
```

Add the component:

<ComponentSource
  src="registry/habi/ui/card.tsx"
  title="components/ui/card.tsx"
/>

Cards usually contain a [Badge](/docs/components/badge), [Button](/docs/components/button) or [Link](/docs/components/link), so add those too.

## Usage

Use only the parts you need, in this order:

```tsx
import {
  Card,
  CardActions,
  CardBadges,
  CardBody,
  CardDescription,
  CardEyebrow,
  CardHeader,
  CardIcon,
  CardImage,
  CardMeta,
  CardMetaItem,
  CardTitle,
} from "@/components/ui/card";

<Card>
  <CardImage /> {/* or <CardIcon /> */}
  <CardBody>
    <CardHeader>
      <CardBadges />
      <CardEyebrow />
      <CardTitle />
      <CardDescription />
    </CardHeader>
    <CardMeta>
      <CardMetaItem />
    </CardMeta>
    <CardActions />
  </CardBody>
</Card>;
```

## Content guidelines

- **One card, one task:** each card is one thing people can start or read.
- **Title as a verb** for services: "Renew your passport", not "Passport renewal".
- **Meta says time, channel and cost:** "About 15 minutes", "Online", "₱950.00", so people can compare before they open anything.
- **Unique link text:** if several cards say "Learn more", add hidden text so each link makes sense on its own.

## Accessibility

### What Habi handles

- **Headings:** each card title is a heading, so screen reader users can jump from card to card.
- **Meta** is a list, so screen readers say how many facts there are. Its icons are decorative: the text carries the meaning.
- **Focus order** follows reading order: title, then actions.

### What you need to do

- **Set the heading `level`** so it follows the page's headings: under an `h2` section, use the default `h3`.
- **Make link text unique.** When cards repeat the same words, like "Learn more", add `sr-only` text after the visible words: "Learn more about renewing your passport".
- **Describe images** that show something the text doesn't. Use `alt=""` when the image only decorates the card.
- **Keep images light** for people on mobile data: compress them, size them close to the card's width, and add `loading="lazy"` to images further down the page. `CardImage` reserves at least 200px of height, so the layout doesn't jump while an image loads.
- **Don't wrap the whole card in a link** when it contains other links or buttons. Nested interactive elements confuse keyboard and screen reader users.
