## Usage

```tsx
import {
  Field,
  FieldDescription,
  FieldError,
  FieldLabel,
} from "@/components/ui/field";
import { Input } from "@/components/ui/input";

<Field>
  <FieldLabel required>Given name</FieldLabel>
  <Input required autoComplete="given-name" />
  <FieldDescription>Write it as it appears on your birth certificate.</FieldDescription>
  <FieldError match="valueMissing">Enter your given name.</FieldError>
</Field>;
```

## Examples

### Validation

Check answers when people submit the form, not while they type. Use Base UI's `Form`: it checks every field, then moves focus to the first one with a problem. Add one `FieldError` for each problem, with `match` set to the check that failed.

<ComponentPreview name="text-input-validation" />

### Errors from your server

When your own code finds the problem, set `invalid` on the field and `match` on the error. Without `match`, the error only shows for the browser's own checks.

<ComponentPreview name="text-input-server-error" />

### Disabled

Only disable a field when people can't change the answer, and say why in the description.

## Writing

- **Labels** say what to enter: "Given name", not "Name 1".
- **Placeholders** show an example ("For example, Juan"). Never put instructions in a placeholder: they disappear when people start typing.
- **Required fields:** mark them with `FieldLabel required` and the `required` attribute, and say "\* means required" once near the top of the form. If most fields are required, mark the optional ones "(optional)" instead.
- **Error messages** say what's wrong and how to fix it: "Enter your email address in the right format, like juan@example.com", not "Invalid input".

## Accessibility

- **Labels:** every input has a visible label, linked to it, so clicking the label focuses the input and screen readers read it.
- **Descriptions and errors** are linked to the input with `aria-describedby`, so screen readers read them when the input gets focus.
- **Autocomplete:** set `autoComplete` on fields about the person, like `given-name`, `email` or `tel`, so browsers can fill them in (WCAG 1.3.5).
- **Validation:** errors appear after submitting, and focus moves to the first field with an error. Each error has an icon and text, not just a red border.
- **Text size:** inputs use 16px text, so phones don't zoom in when people tap them.
- **Focus:** a 2px blue border shows which field is active, even on a field with an error.
